# mdtranslate

Инкрементальный перевод markdown-документации, **не затирающий уже существующий
перевод**. Если в оригинале поправили один абзац, к модели уедет только этот абзац,
а остальной файл — включая ручную вычитку — останется побайтово тем же.

Инструмент ничего не знает про конкретный репозиторий, ветку или язык: всё берётся
из TOML-конфига. Один и тот же код переводит любой проект на любой язык.

## Установка

```bash
pip install "git+https://github.com/deliseev/mdtranslate@v0.1.0"
```

Для Gemini нужен дополнительный пакет:

```bash
pip install "mdtranslate[gemini] @ git+https://github.com/deliseev/mdtranslate@v0.1.0"
```

OpenAI-совместимый провайдер работает на голом `urllib` — ему ничего не нужно.
Требуется Python ≥ 3.11 (`tomllib` из stdlib).

## Быстрый старт

```bash
mdtranslate --config translate-config.toml --dry-run
```

Запускать **из корня репозитория с документацией** — пути в конфиге относительные.
Режим `--dry-run` ничего не меняет и не требует ключей API: он печатает промпты,
которые ушли бы к модели, и сообщает, какие файлы были бы записаны.

За основу конфига можно взять [`examples/translate-config.toml`](examples/translate-config.toml).

## Как это работает

1. **Определяем, что изменилось.** В `[state].sync_file` лежит хеш коммита оригинала,
   до которого всё обработано. Диффим его с текущим `[source].ref` — получаем список
   изменённых, добавленных и удалённых файлов. К ним добавляются файлы из очереди
   `[state].pending_file` — каждый со **своей** базой, а не с общим маркером.
2. **Режем на блоки.** Файл разбирается на блоки (абзацы, заголовки, списки, блоки
   кода). Гарантия: `join(split(x)) == x` побайтово — форматирование не портится.
3. **Сопоставляем оригинал с переводом.** Блоки кода не переводятся и совпадают
   байт-в-байт, поэтому служат якорями. Если сопоставить надёжно не вышло, файл
   **пропускается целиком** — лучше не тронуть, чем затереть.
4. **Планируем.** Диффим старый и новый оригинал: неизменившиеся блоки берём из
   существующего перевода как есть, изменившиеся и новые отправляем на перевод,
   удалённые выбрасываем.
5. **Пакуем в запросы.** Ограничение бесплатных тарифов — число запросов, а не токенов,
   поэтому в один запрос кладётся работа сразу по нескольким файлам, пока не исчерпан
   бюджет `max_request_chars`. Крупный файл естественным образом уезжает один.
6. **Переводим.** Модель получает **полный** текст документа как контекст плюс текущий
   перевод как эталон терминологии, но переводит только куски, обёрнутые в якоря
   `⟦S7⟧…⟦/S7⟧`, и возвращает только их. Непереведённые блоки физически не могут быть
   испорчены, потому что модель их не возвращает.
7. **Публикуем.** Каждый переведённый файл коммитится и пушится **сразу**, а черновой PR
   открывается на первом же коммите. Поэтому убитый посреди работы раннер не уносит
   с собой ни переводы, ни уже потраченную квоту.
8. **Прикладываем оригиналы.** К каждому переведённому блоку в PR добавляется
   комментарий ревью с исходным текстом — иначе в диффе виден только результат
   и сравнивать его не с чем.

### Отказоустойчивость

| Ситуация | Что происходит |
|---|---|
| Кончилась дневная квота | Переключаемся на следующего провайдера; если их нет — остаток уходит в очередь и переводится в следующий прогон |
| Модель вернула битый ответ | В очередь падает только затронутый файл, остальные файлы батча принимаются |
| Раннер убит посередине | Всё, что успело перевестись, уже закоммичено и запушено, PR открыт |
| Перевод не сопоставился | Файл не тронут, помечен как требующий ручной работы и **остаётся в очереди** |

Коды возврата: `1` — нужно вмешательство человека (есть непереведённые из-за
структуры файлы или файлы отложены не из-за квоты), `0` — во всех остальных
случаях, включая исчерпанную квоту. В `--dry-run` всегда `0`.

Это различие важно: квота кончается штатно и почти каждый день, и если такой
прогон красить в красное, настоящая поломка станет неотличима от обычного дня.

### Память переводов

Если включена секция `[memory]`, инструмент ведёт базу пар «оригинал — перевод»
с ключом по хешу исходного текста, и перед обращением к модели заглядывает в неё:

- **точное совпадение** снимает блок с перевода совсем — одинаковый текст в разных
  главах переводится один раз;
- **похожее** (по умолчанию от 0.8 схожести) не подставляется молча: сегмент всё
  равно уходит модели, но вместе с прежним оригиналом и прежним переводом и
  инструкцией внести минимальную правку.

Второе — главное. Без него правка одного пункта в списке из десяти заставляет
переводить блок заново, стирая девять вычитанных человеком пунктов. Подход
известен как [Neural Fuzzy Repair](https://aclanthology.org/P19-1175/).

База пополняется двумя путями: новые переводы запоминаются по ходу прогона, а
уже переведённые файлы вчитываются перед планированием — так правка человека
становится эталоном для остальных файлов.

Чтобы починка работала, шаблон промпта должен содержать `{repairs}` (см. пример
конфига). Без этого плейсхолдера подсказки просто никуда не попадут.

**Неверная пара хуже отсутствующей** — она подставится молча и навсегда. Поэтому
запись строже чтения:

- пары берутся только из **уверенно выровненных** файлов: у прозы сигнатура всегда
  одна и та же, поэтому при низкой уверенности совпадения внутри длинного прогона
  абзацев позиционные, и один пропущенный абзац сдвинул бы все последующие;
- пара отбрасывается, если отношение длин выходит за `min_length_ratio` /
  `max_length_ratio`;
- блоки кода в базу не попадают: они не переводятся.

На реальном корпусе (4294 пары) порог длин отсеял 5 пар, и четыре из них —
настоящие рассогласования в файлах, прошедших проверку уверенности. То есть это
работающая вторая линия защиты, а не формальность.

Формат базы — JSONL, по записи на строку, отсортировано по ключу: новая запись
это добавленная строка, поэтому коммиты не превращаются в перезапись файла.

```json
{"h":"<sha256[:16]>","s":"<оригинал>","t":"<перевод>"}
```

Оригинал хранится рядом с хешем: он нужен нечёткому поиску и промпту починки, а
заодно делает базу читаемой при разборе проблем. Порядок величины — около 1.6 МБ
на 3700 записей.

### Непереводимые файлы чинятся сами

Файл, который не удалось сопоставить, из очереди не выбывает. Перепроверка ничего
не стоит — выравнивание считается локально, до обращения к API, — поэтому каждый
прогон пробует его заново и молча пропускает, пока структура не будет починена.
Как только человек её поправит, файл переведётся в тот же прогон.

Это важно: маркер синхронизации к тому моменту уже ушёл вперёд, и файл, выброшенный
из очереди, не всплыл бы больше никогда.

### Перевести файл заново целиком

Отдельного ключа для этого нет и не нужно. Полный перевод — частный случай
«перевода файла, которого ещё нет»: убираем существующий перевод и указываем базой
пустое дерево git, тогда все блоки становятся новыми.

```bash
rm <файл>
printf '%s\t%s\n' "$(git hash-object -t tree /dev/null)" "<файл>" >> <pending_file>
```

Решение осознанно принимает человек и фиксирует его в репозитории — инструмент сам
никогда не перезаписывает перевод целиком, потому что не может отличить «перевод
плохой» от «я не смог его разобрать».

Ограничение: на больших главах это непроверенная территория. Самый крупный успешно
обработанный ответ содержал 79 сегментов, а полный перевод большой главы — около 281.
При неполном ответе файл остаётся нетронутым и уходит в очередь: безопасно, но может
не сдвинуться с места.

## Что делать, если с переводом что-то не так

### Сначала: прогон покраснел — это авария?

Не обязательно. Код возврата `1` означает «нужно вмешательство», и есть ровно два
повода:

- в сводке есть строки **«нужен ручной перевод»** — файл не удалось сопоставить;
- файлы **отложены не из-за квоты** — например, провайдер вернул ошибку.

Исчерпанная дневная квота отложенными файлами код возврата **не** портит: очередь
разгребётся сама, когда лимит обновится, и в логе будет прямо сказано, что это
штатный режим. Смотрите сводку в конце прогона, а не только цвет галочки.

### Файл попал в «нужен ручной перевод»

Значит структура перевода разошлась со структурой оригинала настолько, что
сопоставить блоки не удалось. Файл **не тронут** — это защита, а не поломка: иначе
пришлось бы перевести его целиком, затерев существующий текст.

Из очереди файл при этом не выбывает и перепроверяется каждым прогоном **бесплатно**,
так что достаточно починить структуру — и он вернётся в работу сам.

Как разобраться:

```python
from mdtranslate.translator import MarkdownSplitter, BlockAligner
s, a = MarkdownSplitter(), BlockAligner()
base = s.split(open("<оригинал на базовом коммите>").read()).blocks
ru   = s.split(open("<перевод>").read()).blocks
al = a.align(base, ru)
print(len(base), len(ru), len(al.mapping), al.confident)
```

Что обычно оказывается причиной:

- **Перевод обёрнут в ограждение.** Если первая строка файла — <code>```markdown</code>,
  весь текст лежит внутри блока кода: он и на сайте отрисуется как код, и парсер
  увидит вместо сотен блоков один. Лечится удалением двух строк. След старых
  инструментов, писавших ответ модели на диск без проверки.
- **Блоки склеены или разбиты.** Число блоков отличается на единицы, доля совпадения
  чуть ниже порога. Восстановите пустые строки там, где они есть в оригинале.
- **Перевод правда неполный.** Тогда либо дописать вручную, либо осознанно
  перевести файл заново (рецепт выше) — с потерей текущего текста.

### Память подсунула неверный перевод

Неверная пара в базе хуже отсутствующей: она подставляется молча и навсегда.
Защиты (только уверенное выравнивание плюс границы длин) ловят не всё — на реальном
корпусе из 4294 пар порог длин отсеял 5, и четыре были настоящими рассогласованиями
в файлах, **прошедших** проверку уверенности.

Если заметили, что в перевод попал явно чужой текст:

1. **Найдите запись.** База — обычный JSONL, ключ считается от исходного текста:

   ```bash
   grep -F "$(head -c 60 <<<'кусок оригинала')" <memory_file>
   ```

2. **Удалите строку** из файла базы и закоммитьте. Инструмент переведёт этот блок
   заново при следующем прогоне.

3. **Проверьте соседей.** Рассогласование обычно не одиночное: если абзацы съехали
   на один, испорчена вся серия. Прогоните выравнивание для этого файла (код выше) и
   посмотрите на пары вокруг.

4. **Ужесточьте пороги**, если такое повторяется: поднимите `min_length_ratio` и
   опустите `max_length_ratio` — они замерены по корпусу и вычищают грубый мусор,
   но их можно сузить под свой материал.

Пересобрать базу с нуля безопасно: удалите файл базы, и он наполнится заново из
уже переведённых файлов при следующих прогонах.

### Модель вернула не то

Ответ проверяется строго: ожидаются ровно запрошенные якоря, непустые. Любое
расхождение — файл **не изменяется** и уходит в очередь, а в логе появляется
«Неполный ответ по …». Разовый сбой лечится следующим прогоном сам.

Если повторяется на одном и том же файле — почти всегда объём: модель не удерживает
дисциплину якорей на сотнях сегментов. Переведите такой файл по частям или
переключитесь на модель с большим окном вывода.

## Ключи запуска

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `--config PATH` | `translate-config.toml` | Путь к конфигу |
| `--dry-run` | выключен | Не обращаться к ИИ и ничего не менять: печатать промпты. Ключи API не нужны |

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `GEMINI_API_KEY` | для провайдера `gemini` | Ключ Google Gemini |
| `OPENAI_API_KEY` | для провайдера `openai` | Ключ OpenAI-совместимого сервиса |
| `GH_TOKEN` | в CI | Нужен `gh` для создания PR. Пушу не нужен: `actions/checkout` оставляет учётные данные в git |
| `GITHUB_REPOSITORY` | в CI | Подставляется GitHub Actions автоматически; без неё не публикуются комментарии с оригиналами |

Имена переменных с ключами задаются в конфиге (`api_key_env`) — сами ключи в конфиг
не попадают. Провайдер без ключа просто пропускается с сообщением в логе.

## Конфиг

### `[source]` — откуда берём оригинал

| Ключ | Пример | Смысл |
|---|---|---|
| `ref` | `"origin/main"` | Git-ссылка на оригинал |
| `include` | `["*.md"]` | Glob-шаблоны переводимых файлов |
| `exclude_paths` | `[".github"]` | Исключаемые каталоги (сравнение по сегментам пути, не по подстроке) |
| `exclude_files` | `["readme.md"]` | Исключаемые имена файлов, без учёта регистра |

### `[target]` — куда кладём перевод

| Ключ | Пример | Смысл |
|---|---|---|
| `branch` | `"ru"` | Ветка перевода, в неё же открывается PR |
| `language` | `"Russian"` | Подставляется в промпт как `{language}` |
| `branch_prefix` | `"translate/sync-"` | Префикс временных веток; к нему дописывается метка времени |
| `pr_label` | `"translate"` | Метка на PR. Должна существовать в репозитории |
| `pr_title` | — | Заголовок PR |
| `pr_body_template` | — | Описание PR; плейсхолдеры `{translated}`, `{skipped}`, `{pending}` |
| `review_comment_template` | — | Комментарий с оригиналом у строки перевода; плейсхолдер `{source}` |
| `max_review_comments` | `300` | Потолок числа таких комментариев на один PR |

### `[state]` — прогресс между прогонами

| Ключ | Смысл |
|---|---|
| `sync_file` | Хеш коммита оригинала, до которого всё обработано |
| `pending_file` | Очередь: файлы, до которых прогон не добрался или не смог обработать |

Оба коммитятся вместе с переводами — каждый коммит оставляет самосогласованное
состояние, поэтому оборванный прогон можно продолжить. Если `sync_file` отсутствует,
первый прогон создаёт его на текущем коммите и ничего не переводит.

**Формат очереди** — по строке на файл, разделитель табуляция:

```
37fae6b5305680c418f5c51b6da67026e065493e	generics.md
```

Слева — коммит оригинала, которому соответствует **текущий перевод этого файла**,
а не общий маркер. Хранить базу рядом с путём обязательно: `sync_file` продвигается
вперёд уже на первом коммите прогона, и если диффить отложенный файл от него,
изменения окажутся позади базы — переводить будет «нечего», а устаревший текст
молча останется навсегда.

Строка без корректного SHA не обрабатывается: файл остаётся в очереди с пометкой
в логе, чтобы базу вписал человек.

### `[prompt]` — как формируется запрос

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `template` | — | Шаблон промпта; плейсхолдеры `{language}`, `{glossary}`, `{source}`, `{repairs}` |
| `context_mode` | `"full"` | `full` — весь документ как контекст, `window` — только соседние блоки |
| `window_blocks` | `20` | Сколько соседних блоков брать при `context_mode = "window"` |
| `max_request_chars` | `200000` | Бюджет символов на один запрос; им же определяется батчинг |

### `[prompt.glossary]` — обязательные термины

```toml
[prompt.glossary]
slice = "срез"
pointer = "указатель"
```

Отдельной секцией, а не инлайн-таблицей: инлайн-таблица в TOML обязана умещаться
в одну строку. Секция должна идти **после** всех остальных ключей `[prompt]`, иначе
многострочный `template` окажется внутри глоссария.

### `[memory]` — память переводов

Секция необязательная: без неё (или с пустым `file`) память выключена и поведение
прежнее.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `file` | `""` | Путь к базе JSONL. Пустой — память выключена |
| `fuzzy_threshold` | `0.8` | Ниже этой схожести прежний перевод не предлагается на починку |
| `min_length_ratio` | `0.4` | Нижняя граница отношения длин перевода к оригиналу |
| `max_length_ratio` | `2.6` | Верхняя граница того же отношения |

### `[[providers]]` — цепочка провайдеров

Порядок значим: когда у провайдера кончается квота, работа продолжается на следующем.

| Ключ | Смысл |
|---|---|
| `name` | `gemini` или `openai` |
| `model` | Идентификатор модели |
| `api_key_env` | Имя переменной окружения с ключом |
| `base_url` | Только для `openai`; любой endpoint с `/chat/completions` — OpenAI, OpenRouter, Ollama, LM Studio |

Добавить нового провайдера — это класс с методом `translate(request) -> str`,
поднимающий `QuotaExhausted` при исчерпании лимита, плюс строка в словаре `PROVIDERS`.
Оркестратор при этом не меняется.

## Запуск в GitHub Actions

```yaml
- uses: actions/checkout@v4
  with:
    fetch-depth: 0        # нужен полный дифф между коммитами

- uses: actions/setup-python@v5
  with:
    python-version: "3.11"

- run: pip install "mdtranslate[gemini] @ git+https://github.com/deliseev/mdtranslate@v0.1.0"

- name: Configure git identity      # инструмент коммитит сам
  run: |
    git config user.name "github-actions[bot]"
    git config user.email "github-actions[bot]@users.noreply.github.com"

- run: mdtranslate --config translate-config.toml
  env:
    GEMINI_API_KEY: ${{ secrets.GEMINI_API_KEY }}
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    PYTHONUNBUFFERED: "1"
```

Джобу нужны права `contents: write` и `pull-requests: write`. Пушу отдельный токен
не требуется: `actions/checkout` оставляет учётные данные в конфиге git.

Ветка перевода должна быть **веткой по умолчанию** репозитория, если `checkout`
вызывается без `ref:` — иначе инструмент будет искать переводы не там.

## Локальный боевой прогон

Инструмент написан для CI и на настоящем прогоне делает всё всерьёз: создаёт ветку
и **переключает** на неё рабочий каталог, коммитит переводы, пушит в `origin` и
открывает PR. Чтобы прогнать по-настоящему без последствий — работайте в отдельном
клоне.
